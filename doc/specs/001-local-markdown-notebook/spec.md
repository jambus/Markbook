# Feature Specification: Obsidian Vault 本地笔记

**Status**: Draft  
**Priority**: P1  
**Depends on**: None

## User Stories

### US1 选择 Vault 并快速记录（P1）

用户可以选择已有 Obsidian Vault，在指定的每日笔记目录中打开或创建当天笔记，
使用所见即所得编辑器记录内容，并在离开编辑器或应用退出前可靠保存。

**Acceptance**: 新建含中文、列表和链接的笔记，重启应用后内容逐字一致。

### US2 浏览与查找（P1）

用户可以按文件夹和最近修改顺序浏览笔记，并通过标题、正文、标签和双向链接
找到目标笔记。

**Acceptance**: 在 1,000 篇笔记的测试库中输入关键字，可得到正确结果且输入
过程无明显卡顿。

### US3 文件可迁移（P1）

用户可以将完整笔记本作为普通目录备份和恢复，不依赖 Markbook 专有数据库。

**Acceptance**: 将目录复制到新安装环境后，笔记与附件引用仍可打开。

## Functional Requirements

- **FR-001** 系统必须将每篇笔记保存为 UTF-8 `.md` 文件。
- **FR-002** 系统必须保留用户 Vault 中的文件名、目录结构和相对链接；标题变化
  不得自动移动或重命名文件。
- **FR-003** 系统必须提供自动保存并防止异常退出丢失已输入内容。
- **FR-004** 系统必须提供删除与可恢复的回收站流程。
- **FR-005** 系统必须支持标题和正文搜索。
- **FR-006** 索引损坏或丢失时必须能从文件重建。
- **FR-007** 系统必须正确处理空标题、重名标题和非法文件名字符。
- **FR-008** 用户必须可以配置每日笔记目录；默认快速记录进入当天的每日笔记。
- **FR-009** 编辑器必须支持常用 Markdown、`[[双向链接]]` 和 `#标签`，并以
  所见即所得方式呈现。
- **FR-010** 每次编辑必须持续自动保存，并提供手动保存入口。
- **FR-011** 回收站中的笔记和附件必须可恢复，并作为 Vault 内容参与同步。

## Out of Scope

拍照处理、同步协议、反向链接视图、关系图谱和插件生态不属于首版范围。
