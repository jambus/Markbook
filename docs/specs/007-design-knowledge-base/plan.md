# Implementation Plan: 项目设计知识库

## Technical Context

- 设计知识库以仓库内 Markdown 维护，路径为 `docs/design/`。
- 文档面向 Android APK 与 HarmonyOS HAP，描述行为和状态，不绑定特定 UI 框架。
- `docs/specs/004-harmony-4-5-compatibility/contracts/vault-contract.md` 是文件格式与事务语义的唯一契约来源；设计文档只引用和呈现这些约束。
- Apple Human Interface Guidelines 是导航层级、上下文保留和动效目的性的参考来源；具体控件与手势仍优先采用目标平台约定。

## Delivery Phases

1. 定义跨端设计原则和文档使用规则。
2. 规定高频组件的用途、状态、触发与无障碍要求。
3. 固化每日笔记编辑与拍照处理的用户流程、失败恢复和验收点。
4. 将导航和动效的跨端规则纳入组件规范、核心流程与评审清单。
5. 提供可用于需求、设计、代码和真机验收的评审清单。

## Constitution Check

- 设计要求必须维护 Vault 为唯一事实源，不能引入私有正文或附件副本。
- 核心操作须优先保证可恢复和可理解，不能以静默失败或静默覆盖换取简化交互。
- 两端可使用不同实现，但输出 Markdown、附件和关键状态语义必须一致。
- 规范以可检查的用户行为陈述，不将未经真机验证的平台假设写成事实。

## Risks

如果文档只停留在视觉偏好而没有状态、边界与验收条件，开发时仍会产生分歧。通过将每个流程对应到现有规格号和评审清单来降低此风险；平台受限时记录差异及原因，不得静默偏离。
