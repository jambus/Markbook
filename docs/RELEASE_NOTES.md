# Markbook Release Notes

本文档记录 Markbook 每个可识别版本的功能范围、交付状态、兼容性说明和后续事项。
Android APK 与 HarmonyOS HAP 分别维护安装包版本；两端共享 Vault 契约，但不因功能
相近而复用版本号或隐含彼此已经完成验收。

## 版本管理规则

- 版本号采用 `MAJOR.MINOR.PATCH`。`1.0.0` 之前为开发阶段：`MINOR` 表示一组可体验的
  功能迭代，`PATCH` 表示不扩大功能范围的修复或小幅体验优化。
- Android 的 `versionName` 使用本文档中的完整版本号，`versionCode` 每次生成可分发
  安装包时单调递增，不得复用已经发布过的值。
- 每次准备新版本时，先在本文档新增版本条目，再同步平台规格、任务状态和安装包配置。
- 版本条目必须区分“开发基线”“候选版本”和“已发布”；只有完成对应真机验收并留存
  构建记录后，才能标记为“已发布”。
- 尚未完成的优化不写入“已实现功能”，统一关联到对应编号规格的未完成任务。

## 0.1.0 — Android APK 当前开发基线

**基线日期**：2026-08-26  
**状态**：开发基线，Mate 60 HarmonyOS 4 真机发布验收尚未完成  
**安装包版本**：`versionName = 0.1.0`，`versionCode = 1`

### 已实现功能

#### Vault 与文件库

- 使用系统目录选择器选择 Obsidian Vault，并持久保留目录访问授权。
- 以 Vault 文件库作为启动页，显示当前 Vault、目录路径、文件夹和 Markdown 笔记。
- 笔记列表显示首段摘要，支持逐层进入目录并在返回时保留浏览上下文和滚动位置。
- 提供固定的“打开今日笔记”入口；每日笔记按 `yyyy-MM-dd.md` 创建或打开。
- 支持将笔记确认后移入 Vault 根目录 `.trash/`；附件不会被连带永久删除。
- 区分空目录和 Vault 无法读取状态，并提供重新选择 Vault 的恢复入口。

#### Markdown 编辑

- 提供基于 WebView 的所见即所得编辑器，以及手动保存和约 600 ms 防抖自动保存。
- 持续显示“未保存”“正在保存”“已保存”和“保存失败”等状态。
- 提供撤销、重做、H1–H5、加粗、斜体、标签、链接和表格工具。
- 对围栏代码块、表格、有序列表、引用、任务列表和 YAML front matter 等结构采用
  原文保留策略，避免打开或保存时静默破坏未编辑内容。
- 保留 Markdown 相对链接语义，并阻止富文本粘贴直接引入任意 HTML。

#### 拍照与附件

- 从编辑器调用系统相机，并在取消时返回原笔记上下文。
- 提供矩形裁剪和四点透视校正，进入处理页即显示可拖动的默认选区。
- 同时保存原图和校正图到 Vault，并在原光标位置插入 Vault 内相对 Markdown 图片链接。
- 附件与正文按事务顺序写入；失败时回滚不完整结果并保留重试路径。
- 插入成功后恢复原阅读位置，支持继续输入和连续拍摄。

#### 设置与同步

- 支持日间/夜间显示模式，并持久保存选择。
- 支持选择 Vault 内的今日笔记目录；设置变化不移动既有笔记或附件。
- 设置页显示中文已启用、English 即将支持，以及应用版本号和构建号。
- 已实现 Google Drive 账号连接、远端文件夹选择/创建、同步范围确认、双向比较、
  进度与取消、冲突副本和结果摘要的初始流程。

### 验证状态

- Markdown 编解码已有 Android JUnit 覆盖。
- 仓库曾记录 Android debug APK 离线构建成功；本版本仍需使用 Java 11+ 环境重新生成
  候选安装包并保存构建记录。
- Mate 60 HarmonyOS 4 的安装、升级、横竖屏、最大字体、拍照中断和重启恢复尚待完成。
- Google Drive 当前实现依赖 Google Play Services，在目标设备上的可用性尚未通过验收，
  不应据此宣称 0.1.0 已具备可交付的远端同步能力。
