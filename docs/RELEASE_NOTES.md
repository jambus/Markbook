# Markbook Release Notes

本文档记录 Markbook 每个可识别版本的功能范围、交付状态、兼容性说明和后续事项。
Android APK 与 HarmonyOS HAP 分别维护安装包版本；两端共享 Vault 契约，但不因功能
相近而复用版本号或隐含彼此已经完成验收。

## 版本管理规则

- 版本号采用 `MAJOR.MINOR.PATCH`。`1.0.0` 之前为开发阶段：`MINOR` 表示一组可体验的
  功能迭代，`PATCH` 表示不扩大功能范围的修复或小幅体验优化。
- Android 的 `versionName` 使用本文档中的完整版本号，`versionCode` 每次生成可分发
  安装包时单调递增，不得复用已经发布过的值。
- 每次准备新版本时，先在本文档新增版本条目，再同步平台规格、任务状态和安装包配置。
- 版本条目必须区分“开发基线”“候选版本”和“已发布”；只有完成对应真机验收并留存
  构建记录后，才能标记为“已发布”。
- 尚未完成的优化不写入“已实现功能”，统一关联到对应编号规格的未完成任务。

## 0.3.0 — 当前开发版本

**状态**：开发实现完成，待 Mate 60 验收（非候选）
**安装包版本**：`versionName = 0.3.0`，`versionCode = 6`

### 当前范围

- 文件库管理：在当前目录新建 Markdown 笔记或文件夹、重命名、移到 Vault 根 `.trash/`，并以 NFC/大小写无关规则防止冲突。
- 文件库左滑：普通条目左滑显示“重命名”和“删除”；删除仍须确认后移到回收站，保留长按和 TalkBack 等价入口。
- 短视频：编辑器“拍摄”可选择拍照或系统相机录视频；视频原样写入当前笔记附件目录并插入相对 Markdown 链接。

### 视频边界

- 视频限制为 180 秒/200 MiB，接受具备有效 MP4/3GP 容器和 video 轨的文件。
- 使用不复制正文的 pending 会话、附件/提交阶段、可取消流式复制、hash 外变保护和 marker 恢复确保异常不会覆盖、重复插入或留下死链接。

### 当前验证

- Android 本地单元测试共 77 项通过，`0 failure / 0 error / 0 skip`，覆盖视频链接
  round-trip、命名冲突、大小/时长、伪容器、rename 不确定与恢复策略。
- 共享 Vault 契约检查通过，debug APK 构建成功；版本为 `versionName = 0.3.0`、
  `versionCode = 6`。
- Mate 60 的文件库左滑、系统相机/播放器、强制结束、限制边界与外部正文变更验收尚未执行，故仍非候选。

## 0.2.0 — 回收站管理

**状态**：开发中
**安装包版本**：`versionName = 0.2.0`，`versionCode = 3`

### 迭代目标

- 在设置页显示当前 Vault `.trash/` 的项目数量。
- 提供明确、不可撤销的“清空回收站”确认。
- 仅永久删除 `.trash/` 的直接内容，不删除 `assets/` 或旧 `attachments/` 附件。
- 后台逐项删除并报告成功数和失败数；部分失败保留未删除项目并允许重试。

### 当前验证

- Android 本地单元测试共 35 项通过，包括清理结果的全部成功、空回收站和部分失败计数。
- `0.2.0` debug APK 已成功构建；Mate 60 上的取消、永久删除、附件保留和 Provider 删除
  失败验收仍待执行。

## 0.1.1 — 可信编辑与保存

**状态**：开发中
**安装包版本**：`versionName = 0.1.1`，`versionCode = 2`

### 迭代目标

- 明确区分笔记加载中、读取成功、新建成功、读取失败和授权失效。
- 已有笔记读取失败时禁止使用默认正文兜底，并提供持续可见的重试、重新选择 Vault 和
  返回文件库入口。
- 将笔记读取和写入迁出主线程，以顺序队列保护同一笔记的写入顺序。
- 使用内容修订号驱动保存状态，旧保存完成不得确认或覆盖较新的输入。
- 将事务恢复扩展到 Vault 的全部用户可编辑目录，并在打开 Vault 时统一执行。
- 增加并发保存、失败重试、后台保存和读取失败的自动化验证。

完成范围由 [`008-android-implementation-hardening`](specs/008-android-implementation-hardening/tasks.md)
的 T810、T815、T824、T825、T828、T829 和 T833 跟踪；全部验收通过前不得标记为候选版本。

### 当前验证

- Android 本地单元测试共 33 项通过，覆盖 Markdown、读取结果区分、修订号保存状态机和
  Vault 恢复策略。
- 共享 Vault 契约检查通过。
- `0.1.1` debug APK 已成功构建；Mate 60 上的读取故障注入、后台保存和异常结束验收待办。

## 0.1.0 — Android APK 当前开发基线

**基线日期**：2026-08-26  
**状态**：开发基线，Mate 60 HarmonyOS 4 真机发布验收尚未完成  
**安装包版本**：`versionName = 0.1.0`，`versionCode = 1`

### 已实现功能

#### Vault 与文件库

- 使用系统目录选择器选择 Obsidian Vault，并持久保留目录访问授权。
- 以 Vault 文件库作为启动页，显示当前 Vault、目录路径、文件夹和 Markdown 笔记。
- 笔记列表显示首段摘要，支持逐层进入目录并在返回时保留浏览上下文和滚动位置。
- 提供固定的“打开今日笔记”入口；每日笔记按 `yyyy-MM-dd.md` 创建或打开。
- 支持将笔记确认后移入 Vault 根目录 `.trash/`；附件不会被连带永久删除。
- 区分空目录和 Vault 无法读取状态，并提供重新选择 Vault 的恢复入口。

#### Markdown 编辑

- 提供基于 WebView 的所见即所得编辑器，以及手动保存和约 600 ms 防抖自动保存。
- 持续显示“未保存”“正在保存”“已保存”和“保存失败”等状态。
- 提供撤销、重做、H1–H5、加粗、斜体、标签、链接和表格工具。
- 对围栏代码块、表格、有序列表、引用、任务列表和 YAML front matter 等结构采用
  原文保留策略，避免打开或保存时静默破坏未编辑内容。
- 保留 Markdown 相对链接语义，并阻止富文本粘贴直接引入任意 HTML。

#### 拍照与附件

- 从编辑器调用系统相机，并在取消时返回原笔记上下文。
- 提供矩形裁剪和四点透视校正，进入处理页即显示可拖动的默认选区。
- 同时保存原图和校正图到 Vault，并在原光标位置插入 Vault 内相对 Markdown 图片链接。
- 附件与正文按事务顺序写入；失败时回滚不完整结果并保留重试路径。
- 插入成功后恢复原阅读位置，支持继续输入和连续拍摄。

#### 设置与同步

- 支持日间/夜间显示模式，并持久保存选择。
- 支持选择 Vault 内的今日笔记目录；设置变化不移动既有笔记或附件。
- 设置页显示中文已启用、English 即将支持，以及应用版本号和构建号。
- 已实现 Google Drive 账号连接、远端文件夹选择/创建、同步范围确认、双向比较、
  进度与取消、冲突副本和结果摘要的初始流程。

### 验证状态

- Markdown 编解码已有 Android JUnit 覆盖。
- 仓库曾记录 Android debug APK 离线构建成功；本版本仍需使用 Java 11+ 环境重新生成
  候选安装包并保存构建记录。
- Mate 60 HarmonyOS 4 的安装、升级、横竖屏、最大字体、拍照中断和重启恢复尚待完成。
- Google Drive 当前实现依赖 Google Play Services，在目标设备上的可用性尚未通过验收，
  不应据此宣称 0.1.0 已具备可交付的远端同步能力。

### 后续优化

0.1 系列的可靠性与体验优化统一由
[`008-android-implementation-hardening`](specs/008-android-implementation-hardening/spec.md)
管理，当前重点包括：笔记读取失败保护、页面与拍照上下文恢复、保存状态与并发写入可信、
以及同步状态可持续发现。
