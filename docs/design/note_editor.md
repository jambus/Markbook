# Markdown 编辑器交互规范

## 目标与边界

编辑器服务于快速记录和可靠保存：用户编辑的是当前 Vault 内的 UTF-8 `.md` 文件，不是应用私有副本。它以所见即所得方式呈现常用 Markdown，但不得改变原有文件名、目录、相对链接或用户未触发的 Markdown 结构。

数据规则以 [本地笔记规格](../specs/001-local-markdown-notebook/spec.md) 和 [共享 Vault 契约](../specs/004-harmony-4-5-compatibility/contracts/vault-contract.md) 为准。

## 页面结构

```text
┌──────────────────────────────────────────────┐
│ 返回 / Vault     笔记标题          拍照  保存 │
├──────────────────────────────────────────────┤
│ 保存状态 / 权限或冲突横幅（仅在需要时出现）   │
├──────────────────────────────────────────────┤
│                                              │
│               可滚动 Markdown 正文            │
│                                              │
├──────────────────────────────────────────────┤
│ 上下文格式工具（可选；不遮挡输入与键盘）       │
└──────────────────────────────────────────────┘
```

标题区域显示文件的可读名称；空标题或无 H1 时可显示“未命名笔记”，但不得借此自动重命名文件。正文是页面焦点，键盘、图片加载或状态提示不能导致光标跳到文首。

## 导航与转场

- 从列表打开笔记时，保留用户对“正在打开此笔记”的方向感；编辑器返回后，列表恢复原滚动位置、筛选和焦点。
- 返回手势/按钮的默认目标是上一级列表。只有存在未保存更改、正在插入照片或发生无法安全离开的错误时，才在当前页面给出继续、重试或放弃的明确选择。
- 编辑器内不使用抢眼的页面入场、光标跳动或保存动画。图片插入可用一次轻微、可跳过的内容更新反馈，但完成状态仍由链接和“已插入”文字明确说明。

## 打开与创建

1. 已授权 Vault 打开后，默认进入配置的当天每日笔记；不存在则创建对应 `.md` 文件。
2. 打开已有笔记时，先显示可阅读内容或骨架，再进入可编辑状态；不得先显示空编辑器。
3. Vault 授权失效时，保留最后已显示的内容和未保存输入（若有），显示权限横幅，并引导“重新选择 Vault”。不得创建替代 Vault 或把正文转存到私有目录。
4. 无笔记时，说明可创建每日笔记或浏览 Vault；不要把空 Vault 视为错误。

## 编辑与 Markdown 行为

- 输入应尽量直接反映到所见即所得内容；常用段落、标题、列表、链接、图片、`#标签` 和 `[[双向链接]]` 均可读、可编辑。
- 光标、选区、滚动位置和正在输入的组合文本优先级最高。自动格式化不得吞字符、破坏输入法组合状态或在用户未完成输入时重排段落。
- 只有用户明确触发的格式操作才改变结构。粘贴、撤销、图片插入与链接编辑都应在光标或选区处发生，完成后让用户继续从原位置输入。
- 无法完整所见即所得呈现的 Markdown 保留原语法并允许编辑，绝不删除或静默改写。

## 保存模型

1. 每次内容变更立即标记为“未保存”。
2. 用户停止连续输入约 600 ms 后开始自动保存；连续输入期间不反复抢占界面。
3. 顶部“保存”随时可触发立即保存，并显示“正在保存…”。
4. 写入完成后才显示“已保存”；写入失败时仍保留全部内存中的编辑内容，并显示“保存失败”及可行动作。
5. 离开页面、进入拍照流程、应用转到后台或即将退出时，尝试提交最新内容；若不能提交，明确阻止会导致未保存内容消失的离开操作，或提供“继续编辑”“重试”“放弃未保存更改”三选项。最后一项须说明只放弃本次未保存修改。

## 保存失败、外部变化与冲突

| 情况 | 编辑器行为 | 用户操作 |
| --- | --- | --- |
| 临时写入失败 | 保留编辑内容与“未保存”状态 | 重试保存 |
| Vault 权限失效 | 停止写入，不覆盖原文件 | 重新选择 Vault |
| 存储空间不足 | 不清空内容；显示空间不足 | 清理空间后重试 |
| 外部文件变化且可安全重新载入 | 说明已更新并保留未保存内容 | 查看更新 / 合并后保存 |
| 同一路径两端都修改 | 不静默覆盖；按 Vault 契约保留冲突副本 | 查看冲突版本 |

“保存失败”不能用短暂提示后消失；在恢复前持续可见。

## 图片插入

拍照入口位于编辑器顶部栏。用户完成图片处理并确认插入后：先完成原图、校正图（如有）及 Markdown 事务，再在当前光标处插入相对路径图片链接；随后将光标置于链接后，方便继续记录。取消或失败保持正文、光标和滚动位置不变。详细步骤见 [拍照流程](capture_flow.md)。

## 退出与恢复

- 返回笔记列表前先处理未保存内容；不因返回而丢失输入。
- 强制结束后，已显示“已保存”的内容必须能够从 Vault 重新打开；未完成附件事务按 Vault 契约恢复或清理，不能留下一个已插入但不可访问的链接。
- 恢复到编辑器时优先恢复同一笔记与可用的阅读位置；无法恢复时解释原因并提供回到 Vault 或重新选择 Vault 的路径。

## 验收示例

- 输入中文、列表、链接和标签，停止输入后显示“已保存”，重启后内容逐字一致。
- 保存失败时继续输入，内容仍存在；恢复权限或空间后可成功保存。
- 拍照插入后继续输入，图片链接位于原光标位置，电脑 Obsidian 可打开。
- 字体放大、横屏和键盘打开时，保存、拍照及当前输入行仍可操作或可见。
