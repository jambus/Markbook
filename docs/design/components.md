# Markbook 组件规范

## 共通规则

组件描述的是语义与状态，不规定具体框架。Android APK 与 HAP 可采用不同原生实现，但名称、结果、禁用条件和反馈必须一致。所有可点击区域应有清晰标签、可见焦点或按压反馈，并满足至少 44 × 44 dp 的触控目标（空间受限的图标操作通过增加热区满足）。

颜色必须同时搭配图标、文字或形状传达状态；正文、控件和图片边界需在深浅色与字体放大时保持可辨认。动态状态须能被辅助技术读出。

## 应用骨架

### 导航层级

Markbook 的信息层级为 `Vault → 文件夹或笔记列表 → 笔记编辑器 → 图片处理`。根页面显示当前 Vault；打开文件夹或笔记属于向下进入，返回应逐层回到上一个可理解的上下文，不应突然跳回根页面。

- 顶级区域用于切换不同信息域（例如“笔记”“搜索”“设置”），只承担导航，不承载“新建”“拍照”等动作。
- 文件夹、搜索结果和笔记列表应保留各自的滚动位置、筛选词与选择状态；返回或关闭处理页不得重置这些状态。
- 模态页面只用于必须先完成、确认或取消的短流程，例如图片处理或放弃未保存改动；关闭后回到启动它的同一位置。
- 系统返回手势或返回按钮始终优先返回上一层；有未保存内容时先进入明确的保存/放弃决策，不能直接丢失。

### 手机 Vault 文件库布局

Android APK 的启动页是 Vault 文件库，不是空白编辑器。它采用“工具在边缘、内容在中心”的笔记应用布局：顶部识别当前 Vault，主体先列文件夹、再列当前目录的 Markdown 笔记，底部保留一个明确的“今日笔记”主入口。

```text
┌──────────────────────────────────────────────┐
│ Markbook                         切换 Vault  │
│ 当前 Vault 名称 / 当前目录路径                 │
├──────────────────────────────────────────────┤
│ 文件夹                                         │
│  ▸ Daily Notes                                 │
│  ▸ Projects                                    │
│                                                │
│ 笔记                                           │
│  2026-07-30                          内容摘要 │
│  会议记录                              内容摘要 │
├──────────────────────────────────────────────┤
│                 打开今日笔记                   │
└──────────────────────────────────────────────┘
```

- 根目录显示 Vault 名称；进入文件夹后显示可读路径。内部的 `.markbook`、临时文件与附件目录不作为普通笔记导航项。
- 文件夹排在笔记前；笔记显示文件名和首段摘要，空文件提供可写的空状态。
- 没有 Vault 时显示产品用途和一个“选择 Vault”主操作，不显示不可用的编辑器或拍照操作。
- 文件库不是桌面侧边栏的缩小复制：手机纵向空间中，目录与笔记列表共享一张可滚动页面；横屏时可由平台实现扩展为双栏。

### 设置页面

设置从文件库顶部栏进入，属于顶级配置页面；返回后回到原文件库位置。

- **显示模式**：提供“日间模式”和“夜间模式”两个互斥选项。选择后立即应用到文件库、设置与编辑器，并在重启后保持；不使用颜色作为“已选中”的唯一提示，须同时显示文字状态或勾选。
- **今日笔记目录**：显示当前 Vault 相对路径；点击后进入仅显示文件夹的选择器。用户点“使用此目录”才提交，返回或取消不改变设置。根目录可选，默认是 `Daily Notes`。
- 设置不得修改、移动或复制 Vault 内容。目录配置只决定后续打开或创建每日笔记的位置；路径变化后，附件链接必须从笔记所在目录重新计算相对路径。

### 顶部栏

**用途**：显示当前上下文与页面级操作。

- 左侧：返回上级，或在根页面显示 Vault/导航入口。
- 中间：当前笔记标题或页面名称；标题过长省略，但可在详情或辅助标签中完整读取。
- 右侧：最多放两项最高频、与当前页面直接相关的操作。编辑器中为“拍照”和“保存”。
- 滚动内容不能遮挡顶部栏；遵守系统状态栏与横屏安全区域。

### 底部操作区

**用途**：承载编辑场景中的次要或多步骤操作。

- 不与系统导航手势冲突；出现键盘时仍保留当前输入位置可见。
- 有未完成的图片处理时，优先显示“取消”“重试”“插入”等下一步，而不是全局功能。

### 转场与动效

动效遵循“变化有来源、有去向”的原则：从列表进入笔记时让标题和内容层级保持连续；打开图片处理时让用户理解正在处理哪一张图片；完成或取消后回到原上下文。

- 优先使用系统组件自带的微妙反馈；自定义动效必须服务于状态、反馈或方向，不能仅为装饰。
- 动效应短、可中断且不阻塞触控、输入、返回或重试。用户再次操作时，立即响应而不是等待前一段动效结束。
- 保存、自动保存、普通列表刷新和连续输入不使用显著运动；用保存状态、进度和内容变化传达结果。
- 支持系统“减少动态效果”设置：减少位移、缩放和视差，保留非动态的状态文字、图标或进度反馈。

## 操作组件

### 主操作按钮

**适用**：一个页面或步骤中最重要且安全的下一步，如“选择 Vault”“插入照片”。

- 同一视觉区域只允许一个主操作；文字描述结果，不用“确定”。
- 执行中禁用重复触发，并显示进行状态；不阻塞阅读或编辑输入，除非当前步骤必须完成。
- 出错后恢复可用状态，保留用户输入，并提供明确的重试或替代操作。

### 次要按钮与图标按钮

**适用**：保存、返回、裁剪、旋转、删除等已知动作。

- 图标按钮必须有可访问名称；不使用没有标签的抽象图标表达关键操作。
- 删除、丢弃和覆盖为破坏性操作，使用明确文字及二次确认；如果可以，优先提供撤销。
- “取消”只放弃尚未提交的当前步骤，不得回滚已安全保存的笔记内容。

### 菜单与溢出操作

**适用**：设置、诊断、低频编辑功能。

- 菜单项用动词开头并按风险排序；破坏性操作与普通操作分组或隔开。
- 关闭菜单不产生副作用；菜单项不可用时给出原因或隐藏，不显示无响应入口。

## 信息与状态组件

### 保存状态

编辑器顶部或靠近标题处持续显示以下之一：

| 状态 | 触发 | 用户可见内容 | 行为 |
| --- | --- | --- | --- |
| 已保存 | 正文已写入 Vault | `已保存` | 可继续编辑 |
| 正在保存 | 防抖保存或手动保存进行中 | `正在保存…` | 防止重复手动保存 |
| 有未保存更改 | 编辑后、保存尚未开始或失败 | `未保存` | 保留内容并可手动保存 |
| 保存失败 | 写入或授权失败 | `保存失败` + 下一步 | 不清空编辑内容；可重试或重新授权 |

不可仅靠短暂 Toast 表示保存是否成功。

### 横幅与行内提示

**适用**：影响当前内容但不需要中断的状态，如 Vault 权限失效、冲突副本或索引重建。

- 放在受影响内容附近，说明影响、原因（可理解时）和主操作。
- 权限失效：提示当前 Vault 不可访问，主操作为“重新选择 Vault”；不自动新建 Vault。
- 冲突：说明原内容未被覆盖，并提供查看两个版本的位置。
- 用户主动关闭后，若状态仍存在，在合适位置保留可重新发现的入口。

### Snackbar / 轻提示

**适用**：不影响后续操作的短暂成功反馈，如“已插入照片”。

- 重要结果必须也能从页面状态或内容中验证。
- 若操作可撤销，提供单个清晰的“撤销”动作，并说明撤销范围。
- 系统相机或文件选择器的取消不显示轻提示。

### 加载、空与错误状态

| 场景 | 必须包含 | 禁止 |
| --- | --- | --- |
| 加载 | 正在进行的对象或骨架；超过短暂等待时给出文字 | 空白页面或无限转圈无说明 |
| 空 | 原因、用户价值和一个下一步 | 将空状态误写成错误 |
| 错误 | 影响、可行下一步、保留内容的说明 | 只展示“发生错误”或技术异常 |
| 无权限 | 所缺权限与重新授权入口 | 静默降级到私有目录 |

## 内容组件

### 笔记列表项

显示标题（或首行替代）、相对日期/修改时间和必要的内容摘要。长按或菜单中的删除进入回收站，不做立即永久删除。空标题使用“未命名笔记”仅作为显示标签，不自动改名。

### Markdown 正文与图片

- 正文优先连续阅读和输入；列表、链接、标签和 `[[双向链接]]` 的显示必须保留其 Markdown 语义与可编辑性。
- 图片应保留原始宽高比，加载中使用稳定的占位区域，加载失败显示相对路径与重试入口。
- 点击图片进入查看或编辑上下文，不应破坏正文选择与光标位置。

### 表单与选择器

标签始终可见，错误靠近字段并描述修复方法。调用系统 Vault 选择器或相机前，先在应用内说明目的；系统界面取消返回后保持原页面与编辑内容。
